1. **Report the discrepancy first:** Point out exactly what contradicts the rules (e.g., "The request asks to use the word 'بهترین', which is forbidden in 04-glossary.md").

## Operational Rules

**1. Read-Only `docs` Folder**
All files and folders inside `docs` are strictly read-only. The AI must never create, edit, or delete any file in this directory. It should only be read to understand the project structure and guidelines.

**2. Utilizing Design Skills**
For any task related to UI/UX and design, you must use the newly added design skills in the system to ensure the final output meets the required standards and quality.

**3. Mandatory Use of Project Tokens and Typography**
The use of design tokens, colors, and typography styles already defined in the project is strictly mandatory. Never use random or hardcoded colors and sizes.

**4. Styling and Animation Tools**
All styling must be done exclusively using Tailwind v4 classes (connected to project tokens). For building and developing animations, use only the GSAP library.

**5. Persian Language (Comments & Content)**
All code comments, commit messages, and user interface texts must be written in Persian to ensure full consistency with the project's glossary and documentation.

**6. Package Management**
When installing any new package or dependency in the project, use only the `npm` command to avoid conflicts with the `package-lock.json` file.

**7. Landing Page Pattern**
All new landing pages (such as the content provided in `landing content.md`) must be implemented to be up to 70% structurally (layout) and visually similar to the reference pattern project.
- The reference files for this pattern are located in the `_landing-2-pattern/` directory (specifically the `src` and `public` folders) at the project root.
- The AI must maintain this structural similarity across all iterations unless the user explicitly requests to override or ignore this layout for a specific case.
**8. Code Health & Error Checking**
Always verify the health of the code you edit or create (e.g., using `npm run lint` or `tsc`) before concluding your response and returning the result to the user. Ensure there are no outstanding errors introduced by your changes.
